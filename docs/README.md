# SruNal: соцсеть и super app

Статус: предложение для обсуждения, реализация ещё не начата. Дата: 11 ноября 2026 года.

**SruNal является соцсетью с лентой и чатами, работающей как super app в Telegram Mini App.** Лента, переписка, сообщества и профиль являются основой самой SruNal. В разделе «Приложения» открываются самостоятельные сервисы, возможности которых можно связывать для удобства.

Состав приложений зафиксирован: **SruDoc** на базе существующего проекта DocGen, **SruDay**, новые **SruPulse**, **SruNotes** и **SruSplit**. Лента и чаты доступны непосредственно в SruNal.

Техническая основа: **React 19 + Vite + TypeScript**, UI/UX существующего SruNal DocGen, **Go** и **PostgreSQL 18**. API и фоновый worker запускаются отдельно, уведомления приходят **в личный чат Telegram-бота**. Приватные поля планируем шифровать на сервере, случайные токены хранить хэшами.

## Основа концепции

- SruNal отвечает за ленту, чаты, сообщества, профиль и каталог приложений.
- У каждого приложения свой интерфейс, данные и основная задача.
- Код приложения находится рядом: `web/src/apps/<id>` на React и `backend/internal/apps/<id>` на Go. Лента и чаты SruNal отделены в `core`.
- Связи включаются для конкретного удобства: поделиться заметкой в чате, добавить встречу в календарь или обсудить общие расходы.
- Можно пользоваться приложениями без публикаций и переписки. Заказы, заметки, календарь и расходы открываются другим только по выбранным разрешениям.
- Начальная аудитория: пользователи существующих проектов, прежде всего студенты. Каталог можно расширять приложениями для других задач.

## Дополнительные приложения

**SruPulse:** показать друзьям «свободен ещё 40 минут» и быстро собрать компанию.

**SruNotes:** создавать обычные текстовые заметки и делиться выбранными заметками с другими.

**SruSplit:** вести общие расходы компании и рассчитывать, кто сколько потратил и кому сколько вернуть.

Подробные сценарии находятся в [описании приложений](02-apps-and-ideas.md).

Социальная основа SruNal и состав пяти приложений выбраны пользователем. Порядок разработки и детали первых версий предложены в документации; новые сервисы ещё не реализованы.
