# SruDay внутри SruNal

SruDay остаётся владельцем календаря и своей базы. SruNal подключает аккаунт только по явному действию пользователя: `POST /api/v1/apps/day/connect` обменивает сохранённый проверенный Telegram payload на пользовательскую сессию настоящего SruDay. Ответ должен подтверждать тот же Telegram ID. Произвольные внешние ID и сервисный токен вместо пользовательского входа не принимаются.

Для этого в SruDay должна проходить проверка payload того же бота. Вход под разными ботами требует отдельного доверенного механизма на стороне SruDay; эта версия его не имитирует. При истёкших данных Telegram необходимо заново открыть Mini App. Без настроенного `SRUNAL_DAY_API_URL` интерфейс сообщает, что подключение недоступно. `SRUNAL_DAY_API_TOKEN` не заменяет пользовательскую сессию и не используется для входа.

Upstream-сессия хранится только в памяти API, максимум десять минут с ограниченным количеством записей. Перенаправления запрещены, чтобы не переслать авторизацию другому адресу. В `app_links` хранится только подтверждённый ID аккаунта. `DELETE /api/v1/apps/day/connect` прекращает новые обращения, сохраняя уже созданные события.

`GET /api/v1/apps/day/events?from={RFC3339}&to={RFC3339}` возвращает выбранную неделю, принимая оба конца периода для недель с переходом летнего времени. Настоящий ответ SruDay `occurrences` преобразуется в `events`; повторения различаются по ID события и времени начала.

`POST /api/v1/day/events` принимает `title`, `starts_at`, `ends_at`, необязательные `all_day` и `location`. Требуются вход SruNal и явное подключение SruDay. Название и место ограничены 200 символами, конец позже начала, длительность до 30 дней. Создаётся только личное событие с `visibility=private`, без группы и автоматического добавления участников. Этот же интерфейс используется после подтверждения пользователем из SruPulse.

Существующее действие Docgen -> SruDay сохранено. Для дедлайна на весь день вычисляются начало и конец локального календарного дня в часовом поясе настроек SruNal; одинаковые начало и конец больше не отправляются.

Настоящий SruDay пока не поддерживает `source_ref` и ключ идемпотентности создания обычного события. Поэтому SruNal не обещает защиту от дубля при потере ответа после успешной записи: автоматического повтора POST нет, перед ручным повтором нужно проверить календарь. Сохранённый результат интеграции Docgen защищает только уже подтверждённые повторы; сбой между записью во внешнем SruDay и сохранением результата остаётся этим ограничением.

Клиентский календарь и ввод времени используют часовой пояс устройства и явно показывают его. Переключение часового пояса аккаунта не переопределяет время `datetime-local` незаметно для пользователя.

Проверки: Go `httptest` для настоящего входа и `occurrences`, приватности создаваемого события, несовпадения Telegram ID, отказов upstream, запрета перенаправлений и календарного дня при DST. Реальные разные Telegram-боты и production SruDay требуют отдельной проверки подключения.
